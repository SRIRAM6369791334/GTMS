# GTMS — Lessons Learned & Categorized Knowledge

## [Architecture_Decisions]
- **[Dynamic_Invoice_Consolidation_From_Polymorphic_Ledgers]**: Consolidating multiple regulatory statutory applications (Lease, Mining, EC, PPT, DGPS, Drone) into unified commercial invoices (Proforma and Tax Invoices) requires flexible polymorphic data mapping. Querying all 7 modules dynamically for a specific customer, extracting non-zero or active projects, mapping their product descriptions and fees to standardized line items, and calculating CGST/SGST (9% each for intra-state) vs IGST (18% for inter-state) delivers a scalable, automated billing pipeline without duplicating invoice records.
- **[Standalone_Asset_Extraction_For_High_Fidelity_PDFs]**: When converting reference PDF designs to HTML/Blade templates, embedding massive base64 image strings (1MB+) bloats Blade templates and slows down parsing. Extracting high-resolution letterheads, authorized seals, and logo assets as lightweight, optimized web assets under `public/images/invoices/*.png` ensures lightning-fast template rendering, clean source code, and pixel-perfect fidelity.
- **[Indian_Currency_Number_To_Words_System]**: Standard Western numbering formats (millions, billions) fail Indian statutory accounting and GST requirements. Implementing an exact Indian numbering algorithm dividing integers by Crores (10,000,000), Lakhs (100,000), Thousands (1,000), and Hundreds (100) ensures legal compliance on all official Tax and Proforma Invoices (e.g. "Rupees One Lakh Fifty Thousand Only").
- **[Module_Document_Tables]**: User explicitly confirmed dedicated document tables per module (`lease_documents`, `mining_documents`, `environment_documents`, `ppt_documents`, `survey_documents`). This ensures clean separation, isolated indexes per module, and avoids locking issues on a single multi-gigabyte table when 1000+ users upload documents simultaneously.
- **[Mineral_Stockpile_Model]**: Transform the legacy product/shop inventory into a domain-specific Mineral Stockpile System: quarries record extracted CBM/Tonnes (`stock_in`), transit dispatches (`stock_out`), and seigniorage/royalty billing fees.
- **[Dynamic_Roles]**: Roles are not static enum strings; they are dynamic rows managed by Super Admin with granular permissions.
- **[Universal_MIMAS_Master_Key]**: Mining entities have state-issued MIMAS registration identifiers containing symbols, letters, and numbers (`TN/MMS-2026/001`). Treating `mimas_no` as a unique indexed master key on `customers` allows instant autofill across other modules (Lease Application wizard, Mining Plans, EC applications), eliminating repetitive data entry and guaranteeing referential consistency across all departmental filings.
- **[Aadhaar_Regulatory_Validation]**: Regulatory mining applications require representative identity verification. Storing `aadhaar_no` as a formatted unique string (`VARCHAR(20)`) with regex validation (`/^[0-9]{4}[ -]?[0-9]{4}[ -]?[0-9]{4}$/`) accommodates user-friendly hyphenated formatting (`9876-5432-1012`) while ensuring 12-digit integrity, strict uniqueness, and automated cross-application population.
- **[Multi_Select_Pivot_Compatibility]**: When migrating an existing single-FK schema (e.g. `mining_applications.mineral_id`) to multi-selection (quarries extracting both Rough Stone and Gravel), use a dedicated pivot table (`mining_application_minerals`) with `foreignId` cascade deletes and composite unique key. Simultaneously preserve the primary column `mineral_id` on the parent table populated with the primary selection ($mineralIds[0]) and provide both `minerals(): BelongsToMany` and `mineral(): BelongsTo` relationships on the Eloquent model. This guarantees 100% backward compatibility for all legacy queries while cleanly supporting multi-select rendering across all downstream views.
- **[Customer_Unique_ID_Domain_Separation]**: In a multi-module regulatory ERP, distinguish clearly between: (1) The client entity's master identifier ("Customer Unique ID"), used to look up and auto-fill applicant profiles across all statutory wizards; and (2) Departmental portal credentials (such as Tamil Nadu government "MIMAS" login User ID and encrypted password in Step 6 / Stage 6.4). Rebranding user-facing labels to "Customer Unique ID" improves operational clarity for staff while preserving the underlying column name `mimas_no` in the database to prevent regression or costly migrations across all dependent models.
- **[Search_Normalization_Aadhaar_Hyphen_Mismatch]**: When Aadhaar numbers are persisted in MySQL in formatted hyphenated notation (`XXXX-XXXX-XXXX`), naive SQL substring queries (`LIKE '%323268689898%'`) completely fail to match raw 12-digit user inputs. Search handlers (both live AJAX autocomplete and form queries) must apply bidirectional normalization: (1) strip non-digits (`$cleanDigits = preg_replace('/[^0-9]/', '', $q)`), (2) match against database columns with `REPLACE(REPLACE(COALESCE(aadhaar_no, ''), '-', ''), ' ', '') LIKE '%$cleanDigits%'`, and (3) re-construct standard 4-4-4 dashed and spaced variations (`$dashed = substr(..., 0, 4) . '-' . ...`) for indexed string equality lookups. This allows users to search seamlessly via raw digits, hyphenated numbers, spaced digits, or partial inputs.
- **[Empirical_Documentation_Reconciliation_Over_Assumptions]**: In legacy brownfield takeovers, never report test metrics or state transitions based on assumed intentions or outdated documentation. Always run live CLI executions (`php artisan test`, `route:list`, SQL information schema queries) and reflect genuine findings (such as label mismatches in UI assertions or actual database columns) into the technical documentation. Truthful transparency creates trust and enables clean, rapid onboarding for new developers without surprises.
- **[Polymorphic_Handlers_And_Financial_Ledger]**: Across diverse statutory workflows (Lease applications, Mining plans, EC filings), personnel allocation and financial accounting follow identical relational patterns. Implementing universal polymorphic tables (`application_handlers` and `application_payments`) with compound keys (`application_type`, `application_id`, `payable_type`, `payable_id`) allows dynamic multi-person assignment and real-time ledger accounting to scale effortlessly across any current or future application modules with zero schema bloat.

## [Workflow_Design]
- **[Sequential_Stages_6]**: Stages 6.1 through 6.6 are strictly sequential; each stage requires designated role sign-off and attached audit reports before unlocking the next stage.
- **[Round_Robin_Inspector]**: Field inspection assignments are automated via round-robin distribution based on district jurisdiction to eliminate manual assignment bottlenecks.
- **[Automatic_Data_Handoff]**: When field surveys (DGPS) or approvals (EC Certificate) complete, verified dimensions, boundary points, and approval numbers automatically propagate to the parent lease/mining record.
- **[Scope_Trimming]**: External logistics transit pass/e-permit issuance and wallet transactions were removed from the office document management scope, keeping the core focus on regulatory compliance, survey tracking, and office document workflows.
- **[Dual_Phase_Document_Intake]**: In complex statutory engineering wizards (Mining Plan & Lease Applications), allowing document uploads directly during intake while keeping full upload/update capability in the post-registration dossier (`/document?id=X`) provides the best user experience. Applicants with all files ready can upload them in Step 6 with instant real-time progress and dropzone auto-matching, while applicants who need time to gather physical revenue maps or clearances can register first and upload into the 6-folder statutory dossier later.

## [High_Concurrency_1000_Users]
- **[Connection_Pooling]**: 1000 simultaneous users can exhaust default MySQL connection limits (max_connections default is typically 151). Must tune MySQL `max_connections` (e.g. 500-1500) or use connection poolers / persistent connections, plus non-blocking query design.
- **[Async_Heavy_Uploads]**: 50MB-100MB files (Orthomosaic, CAD drawings) cannot block PHP-FPM web worker threads. Uploads must be handled via direct chunking or background queue jobs so the web server remains 100% responsive.
## [UI_UX_and_Routing]
- **[Slug_Based_Routing]**: Avoid raw numeric primary key IDs in customer URLs (`/customers/1`) to prevent ID enumeration and improve SEO/clarity. Use readable unique slugs (`/customers/sri-bala-traders`), while keeping graceful ID fallback (`orWhere('id', $slug)`) to ensure legacy hyperlinks never 404.
- **[Dossier_Visual_Hierarchy]**: In dense enterprise ERPs (mining & regulatory compliance), avoid monolithic tab pages. Use split-screen sticky sidebars for entity metadata (PAN, GSTIN, Contacts) and segmented horizontal tabs for operational modules (Leases, Mining, EC, PPT, Surveys, Stockpile) with empty-state illustrations.
- **[Aadhaar_Input_Masking_and_Backend_Normalization]**: User convenience demands seamless numeric input (`987654321001`) without forcing manual typing of dashes. Combining real-time JavaScript input formatting (`input paste keyup` event regex mask grouping digits into `XXXX-XXXX-XXXX`) with backend pre-validation normalization (`preg_replace('/\D/', '', $input)`) guarantees both great UX and database integrity regardless of how the data is submitted (UI typing, copy-pasting, or API requests).
- **[Legacy_Prototype_HTML_Links_Audit]**: Slicing static HTML mockups into Laravel Blade often leaves hardcoded `.html` anchor links (e.g. `href="step5-documents.html"`). In a Laravel application, these inevitably trigger `404 Not Found` because routes are handled dynamically via `routes/web.php`. All internal navigation links must use Laravel route helpers (e.g. `{{ route('step5') }}`) or valid absolute paths (`/step5`), with inactive action buttons using `javascript:void(0)`.
- **[Prototype_Mockup_Purge_In_Wizard_Steps]**: When slicing static HTML prototypes into dynamic multi-step wizard views (such as `createstep5.blade.php`), static classes like `.up` and hardcoded progress counters (e.g. `6 / 19 uploaded`, `32%`) must be replaced with server-side dynamic conditionals (`@if(isset($uploadedDocs[$item]))`). Otherwise, fresh wizard runs incorrectly display dummy documents as already uploaded and mislead the user. All upload actions must be wired via real AJAX `FormData` to backend storage endpoints.
- **[Database_Backed_Draft_Persistence]**: Relying purely on PHP sessions (`session('lease_draft')`) for multi-step enterprise wizards with heavy document checklists (19 items) is prone to session expiry (default 120 mins) and data loss when applicants must pause to obtain offline physical revenue records, FMB sketches, or MIMAS government approvals. Persisting draft records to MySQL (`lease_applications` with `status = 'draft'` and `application_no = 'LA-DRAFT-YYYY-NNNN'`) from Step 1, alongside atomic milestone document records (`lease_documents`), guarantees 100% data durability across days/weeks with one-click resumption (`/application/{id}/resume`).
- **[Honest_Document_State_And_Dual_Validation]**: Never auto-generate dummy files or hardcode `'validated'`/`'uploaded'` statuses in submission loops. Missing files must remain `status = 'pending'` with `file_path = null` and clear "Not Uploaded" badges. Implement dual-level scrutiny: (1) Bulk validation via Process Flow Stage 6.2 "Pass Validation" which automatically marks all verified attachments as validated, and (2) Granular per-document validation (`[✓ Mark Valid]`, `[✗ Flag / Review Note]`, `[Undo]`) with instant AJAX feedback and live audit logging in `activity_logs`.
- **[Model_Casts_Vs_Manual_Crypt]**: In Laravel Eloquent models, when a column has `'password' => 'encrypted'` in its `$casts` array, passing a string already wrapped in `Crypt::encryptString()` results in double-encryption (`encryptString(encryptString($pass))`). This causes the model to decrypt only the outer envelope on access, leaving raw encrypted string gibberish to downstream services. Always pass clean strings when relying on model attribute casts.
- **[Concurrency_Safe_Sequencing]**: Relying on `Model::count() + 1` for official or draft document numbers (e.g. `LA-2026-0005`) inevitably collides when concurrent transactions occur or when soft-deleted rows exist. Always use transaction-scoped row locking (`lockForUpdate()`) alongside `withTrashed()` and extract the true maximum sequence number (`CAST(SUBSTRING_INDEX(application_no, '-', -1) AS UNSIGNED)`) to ensure atomic monotonic incrementation under high load.
- **[Route_Permission_Separation]**: Never bundle state-modifying workflow routes (like `/validate`, `/approve`, `/reject`) under read-only middleware like `permission:application.view`. View permissions must strictly guard read endpoints (`/application`, `/report`), while state transitions require elevated `permission:application.edit` to uphold least-privilege enterprise governance.
- **[Masked_Secret_Form_Placeholders]**: When rendering credentials in editable forms (e.g. MIMAS portal passwords in Step 6), rendering real decrypted passwords into `value="{{ $pass }}"` exposes raw credentials in cleartext within browser DOM and developer inspection tools. Instead, render a well-known placeholder token (`__UNCHANGED__`). On backend submission, if the submitted value equals the placeholder or is blank, retain the existing encrypted record untouched.
- **[Helper_Method_Integrity]**: When refactoring controller classes to add new architectural methods, ensure existing private helpers (e.g., `formatFileSize()`) are preserved, as asynchronous AJAX endpoints (e.g. `uploadDocument`) depend on them for response formatting.
- **[DOM_Prop_Vs_Attr_Toggling]**: For dynamic UI state toggles like password show/hide (`input[type="password"]` to `input[type="text"]`), always use `$(el).prop('type')` instead of `$(el).attr('type')`, ensuring subsequent clicks accurately read the live property rather than the initial HTML attribute.
- **[Folder_Wise_Dynamic_Document_Addition]**: When allowing users to dynamically upload ad-hoc statutory documents into specific statutory folders (e.g. Field Log, Documents, Plan), implement folder-scoped modals that lock the `folder_id` and accept `Document Name`, `Status` (Mandatory/Optional), and `File Upload`. In multi-step wizards without premature DB persistence (Mining Portal), use client-side `DataTransfer` to assign files dynamically to generated hidden file inputs (`custom_doc_files[cidx]`), update overall and folder-level progress counters in DOM, and handle storage upon parent form submit. In database-backed session draft wizards (Lease Application), submit files via AJAX to persist to `LeaseDocument` with `document_field_id = null`, dynamically append `.checklist-row` elements into folder DOM containers, and ensure subsequent wizard steps (Step 7 summary and compliance dossiers) render authentic custom document titles instead of generic item numbers.

- **[Universal_Common_ID_Traceability]**: When transitioning statutory dossiers between sequential departmental modules (e.g. Lease Application -> Mining Plan -> Environmental Clearance), creating disconnected, module-specific primary identifiers (`LA-2026-0011` vs `MP-2026-0005`) breaks cross-departmental audit trails and causes user confusion. Assigning an immutable Universal Common ID (`GTMS-{YEAR}-{SEQUENCE}`, e.g. `GTMS-2026-0011`) indexed across all domain tables preserves referential integrity, enables instant global search, and maintains backward compatibility while allowing module-specific prefixes for official correspondence.
- **[Cross_Module_Document_Cloning]**: Moving an application across modules requires statutory files (Patta, Adangal, FMB, KML) to be accessible in both module dossiers without risk of cross-module file deletion side-effects. Physical file cloning (`File::copy()`) into the target module's dedicated directory (`public/uploads/mining/{mp_app_no}/`) paired with target document table record creation (`MiningDocument` in statutory Folder #2 and Folder #5) guarantees complete module isolation, audit independence, and zero data loss.
- **[Dual_Contact_Architecture]**: When expanding statutory entity profiles to support dual contacts (Primary Authorized Representative alongside Secondary/Site In-Charge Mobile and Person), enforce database schema naming consistency across modules (`secondary_contact_person` and `secondary_mobile_num` on `customers`, `secondary_contact_person` and `secondary_contact_mobile` on `lease_applications`). Add `different:mobile_num` validation rules to avoid duplicate numbers, ensure secondary fields are nullable for backward compatibility with legacy records, and update lookup APIs (`lookupByMimas`) to auto-populate both sets of contacts during multi-step statutory wizard intake.
- **[Cross_Module_Resume_Workflow]**: When moving an application between domain modules (e.g. Lease Application -> Mining Portal), the destination module requires additional domain-specific configurations (Nature of Work, Plan Type, RQP, Safety Distance) that do not exist in the source module. Rather than blocking the move with complex multi-step modal prompts, create the destination draft with an origin link (`lease_application_id`), and provide a prominent `[ ▶ Resume ]` action in the destination master table. Route to the intake wizard with `?resume={id}` to auto-fill all carried data (client, contacts, district, extent, survey numbers, minerals, documents), highlight the resumption with a contextual notification banner, and allow the applicant to manually complete the missing domain fields before final submission. This preserves database integrity, prevents record duplication upon resubmission, and provides a smooth, frictionless UX.
- **[Step_Consolidation_Wizard_Refactor]**: When consolidating a 7-step wizard into 6 steps (merging Step 6 into Step 2), write backwards-compatible aliases for legacy routes (`route('step7')` redirects to `route('step6')`) and dual-populate session draft keys (`$draft['step2']` and `$draft['step6']`). This ensures downstream components, reports, and resumed drafts continue functioning without regression.
- **[HTML5_Pattern_Attribute_Defensiveness]**: Avoid hardcoded strict regex masks like `pattern="[0-9]{10}"` on tel inputs when users or upstream autocomplete APIs might provide numbers with leading zeros (e.g. `06369791335`, 11 digits) or international country prefixes. Use flexible range patterns like `pattern="[0-9]{10,15}"` so HTML5 validation doesn't silently block form submission.
- **[Natural_Sequential_Checklist_Numbering]**: When reordering checklist sections or regulatory folders in multi-step intake wizards (e.g. moving Documents folder to display before Lease Application folder), never leave disconnected item numbering (such as items 8..16 in Folder 1 followed by items 1..7 in Folder 2). Renumbering items sequentially 1 through 19 ensures natural cognitive progression for applicants. Simultaneously synchronize: (1) Blade checklist arrays (`createstep5`), (2) folder tile counters (`createstep4`), (3) AJAX upload metadata and submission array (`CustomerController@uploadDocument` and `@submit`), and (4) ensure dossier views (`viewapplication`) sort naturally by numeric prefix so the entire application pipeline remains 100% harmonious.

## [UI_Bugs]
- **[CSS_Class_Collision_And_Flex_Squeeze]**: When multiple stylesheets or components define the same utility class name (such as `.stat-card`), later definitions overriding the layout with `display: flex; align-items: center; gap: .9rem;` (with horizontal row flow) will forcibly compress all direct children into a single cramped horizontal row. In 4-column layouts (`col-6 col-lg-3`), this causes primary metrics (e.g., `1 / 16`) to wrap vertically across multiple lines (`1 /` above `16`), distorting labels and pushing status badges off-screen. Always use scoped, module-isolated class names (such as `.dossier-kpi-card`) and enforce structured vertical hierarchy (Header label + accent icon, primary metric with `tabular-nums` and `white-space: nowrap`, and footer status chip) for responsive, jitter-free KPI metric presentations.
- **[SoftDeletes_BelongsTo_WithTrashed]**: When a parent model uses `SoftDeletes` (e.g. `Customer`), deleting a parent record sets `deleted_at` timestamp. Child models with standard `belongsTo(Customer::class)` default to querying only non-deleted parents (`whereNull('deleted_at')`), causing `$app->customer` to return `null`. In Blade templates, syntax like `$app->customer->company_name ?? $app->customer->customer_name` fails because accessing `->customer_name` on `null` throws `ErrorException: Attempt to read property ... on null`. Always: (1) add `->withTrashed()` on child `belongsTo` relations for regulatory/audit historical integrity, and (2) use PHP null-safe operator `$app->customer?->...` in views with graceful fallbacks and contextual `Deleted` badges.
- **[Table_Actions_Wrap_And_Color_Consistency]**: DataTables dynamically computes column widths from text content; short column headers like "Actions" (~60px) cause multi-button groups (e.g. 3 buttons = 3x32px + gaps = ~110px) to wrap into an awkward multi-line "L" shape. Always assign an explicit `min-width` (`125px`) to `<th class="text-end">` and enclose buttons in an inline flexbox container (`.table-action-group` with `nowrap`). In addition, avoid template generic `.btn-info` which defaults to vibrant magenta/pink (`#D653C1`), clashing with enterprise palettes; use soft-tinted, theme-matched button variants (`#eff6ff` Navy/Blue for view, `#fef3c7` Gold/Amber for edit, and `#fee2e2` Rose/Red for delete).
- **[Missing_Utility_Class_Contrast_Failure]**: Relying on custom utility class names (such as `.bg-navy`) without ensuring they are registered in the global CSS stylesheet results in browsers silently ignoring the rule. If combined with `.text-white`, the text renders white on an unstyled white/light page background, rendering critical badges invisible. Always explicitly register core theme utility classes (`.bg-navy { background-color: #0F1E4D !important; color: #fff !important; }`) in the primary stylesheet.
- **[Orphan_DOM_Reference_In_Progress_Handlers]**: When purging legacy prototype UI elements (e.g. dummy bulk upload buttons `#btn_upload_all_trigger`), ensure all progress calculation and state update functions (`updateOverallProgress()`) are thoroughly audited for orphan identifier references. In JavaScript, checking `if (btnUploadAllText)` when `btnUploadAllText` was never declared with `let`, `const`, or `var` triggers a fatal `ReferenceError: btnUploadAllText is not defined`. In Promise chains or AJAX callbacks (`.then()`), this uncaught exception causes execution to drop immediately into `.catch(err => alert('Upload error: ' + err.message))`, displaying a confusing error modal to the user even after the backend server has processed and saved the file successfully. Cleanly removing orphan blocks guarantees smooth asynchronous execution.
- **[Blade_Single_Line_Php_Directive_Collision]**: In Laravel Blade, using inline `@php($variable = ...)` can be mishandled by the Blade regex tokenizer. When compiled as `<?php($variable = ...)` without a closing `?>`, the entire downstream template content is treated by PHP as being inside an unclosed PHP block until an `@endphp` is encountered. This prevents intermediate Blade directives (`@if`, `@elseif`, `@foreach`) from compiling into valid PHP code, leading to fatal `ParseError: syntax error, unexpected token "elseif"`. Always use multi-line `@php ... @endphp` blocks for variable declarations and array definitions in Blade templates.
- **[Separate_Page_Document_View_Pattern]**: For regulatory documents (PDF, KML, CAD, images), users require a distraction-free full-canvas view ("separate black page") rather than small inline modal previews. Providing dedicated `<a href="..." target="_blank" rel="noopener noreferrer" class="btn btn-sm btn-outline-info">` View icons triggers native browser high-contrast dark/black canvas PDF viewers. In intake wizards before database persistence, generating temporary Object URLs (`URL.createObjectURL(file)`) allows users to preview newly attached files in separate tabs immediately before committing the form.

## [Database_Integrity_and_SoftDeletes]
- **[Unique_Constraint_Vs_SoftDeletes_Collision]**: In MySQL, standard UNIQUE indexes (`customers_slug_unique`, `customers_mimas_no_unique`, `customers_aadhaar_no_unique`) enforce uniqueness across ALL rows, including soft-deleted rows (`deleted_at IS NOT NULL`). When resolving a customer during application submission or intake, using standard `Customer::find()` or `Customer::where()` ignores soft-deleted records and returns `null`, tricking controllers into calling `Customer::create()`. This triggers fatal `Integrity constraint violation: 1062 Duplicate entry`. Fix: (1) Always resolve existing records with `Customer::withTrashed()`, and restore (`$customer->restore()`) if the applicant is actively submitting under that entity; (2) In model slug generation lifecycle hooks (`booted()`), always check uniqueness with `static::withTrashed()->where('slug', $slug)->exists()` inside a collision loop (`while`) to guarantee monotonically incremented, guaranteed-unique slugs (`base-2`, `base-3`) that never violate database constraints.
- **[Cross_Module_Prefix_And_Sequence_Synchronization]**: When creating statutory dossiers across multiple intake pathways (direct intake vs cross-module promotion), diverge prefixes (e.g. `MDG-` vs `MP-`) cause reporting confusion and break sequential gap-detection. Standardizing on a single prefix (`MP-` paired with Universal Common ID `GTMS-`), extracting the maximum sequence monotonically with regex (`CAST(SUBSTRING_INDEX(...) AS UNSIGNED)`), and enforcing transaction-scoped row locks (`lockForUpdate()`) completely eliminates sequence collisions under high concurrency.
- **[Test_Database_Transactions_And_Unique_Constraints]**: In automated feature test suites running against persistent development MySQL databases (`gtms_data`), always apply Laravel's `DatabaseTransactions` trait so test mutations roll back automatically upon test teardown. Furthermore, test generators creating models with unique indexed keys (e.g. `Customer::$aadhaar_no`, `Customer::$pan`, `Customer::$email`) must generate randomized values (`rand()`) to prevent `UniqueConstraintViolationException: 1062 Duplicate entry` across multiple test runs or failed previous transactions.

## [DOM_Optimization_and_Modals]
- **[Loop_Modal_Purge_To_Dynamic_Instance]**: Rendering Bootstrap modal HTML markup inside a `@foreach` loop over 20-50 document records inflates the DOM by thousands of lines, degrades page render performance, and creates orphan modal backdrops when multiple modals are opened and closed. Instead, render a single modal outside the loop and dynamically populate the action URL, title, and target identifiers via JavaScript click handlers using `bootstrap.Modal.getOrCreateInstance()`.
- **[Masked_Secret_Blur_Resilience]**: When rendering secret credential fields masked with a placeholder (`__UNCHANGED__`) alongside HTML5 `required`, focusing into the field to edit it clears the placeholder. If the user clicks away without typing, leaving the value empty triggers native browser form blocking on submission. Storing a boolean indicator (`data-has-saved="1"`) and binding a `blur` event handler to restore `__UNCHANGED__` if the input is left blank seamlessly prevents validation lockouts.
- **[Multi_Step_Wizard_Navigation_Gating]**: In multi-step wizards (such as 6-step statutory EC Certificate issuance), unconditionally rendering stepper header indicators as direct hyperlinks (`<a href="...step/N">`) allows applicants to skip mandatory prerequisite stages and land on uninitialized future steps with missing draft sessions and broken fallbacks. To enforce deterministic sequential flow: (1) Render future uncompleted steps as disabled, non-clickable elements (`cursor: not-allowed; opacity: 0.65`) while allowing backward navigation only to active and completed stages (`$isDone || $isActive`); (2) Enforce server-side controller route guards (`if ($step > 1 && empty($draft['step1']))`) that gracefully redirect direct URL deep-links back to Step 1 with a clear explanatory flash message.
- **[Read_Only_Dossier_Vs_Creation_Wizard_Separation]**: In statutory ERP tables (such as `/ec-certificate`), the "View" action button on an already-issued, active certificate should NEVER link into an intermediate stage of a creation wizard (such as `/ec-certificate/step/3`). Creation wizards contain editable state machine controls ("Back to Step 2", "Continue to Store Documents") which confuse users reviewing an official document. Always separate concerns: create a dedicated read-only view route (`/ec-certificate/{id}`) rendering an authentic printable order with letterhead, QR seal, and conditions, while reserving `/ec-certificate/step/1` strictly for issuing new certificates. In cross-module index tables, contextually show `View Issued Certificate` if a grant already exists, or `Issue Certificate` if approved and pending grant.
- **[Symmetrical_Route_Gating]**: Guarding only GET routes in a multi-step state machine is insufficient. A client can directly POST to `/step/4` or `/step/6` even if intermediate steps were never saved. Both GET display handlers and POST submission handlers must enforce `$maxUnlockedStep` checks, redirecting unauthorized attempts back to the earliest incomplete step and preventing session state corruption.
- **[Safe_Upload_Directory_Sanitization]**: When creating directories dynamically based on entity codes (such as `uploads/ec_certificates/{project_code}`), project codes containing slashes or special characters (`ENV/B2#2026`) can cause unintended directory nesting or path traversal. Always sanitize dynamic components using regex (`preg_replace('/[^a-zA-Z0-9_-]/', '_', $code)`), create directories safely with `File::ensureDirectoryExists($destPath, 0755, true)`, and automatically unlink superseded draft files upon replacement.
- **[Dynamic_Resumption_Document_Deduplication]**: When transitioning records between statutory modules (Lease to Mining Plan), document slots are pre-created during transition. Resuming the application intake wizard (`/newapplication?resume={id}`) and submitting standard or custom files must update existing `MiningDocument` records in place rather than calling `MiningDocument::create()`, which causes duplicate document rows and invalid folder count totals.
- **[Carried_Document_Client_Progress]**: In multi-step wizards where documents are carried over from a prior module or resumed draft, client-side progress bars and counters must inspect both newly selected files (`inp.files.length > 0`) and existing pre-filled files (`inp.getAttribute('data-has-existing') === '1'`). Otherwise, the stepper progress displays 0% and misleadingly shows attached documents as missing until the user manually touches each file input.
- **[Multi_Faceted_Statutory_Filtering]**: In a multi-module regulatory system tracking entities across diverse statutory stages (Lease, Mining, Environment, EC, Surveys), full-text search must be paired with structured multi-faceted filters: (1) District dropdown matching parent customer profiles and child application jurisdictions, (2) Application module type mapping to polymorphic relations (`whereHas`), (3) Dynamic Date Range query scoping to application creation timestamps (`created_at`) rather than just customer registration dates, and (4) Dual-contact number search across primary (`mobile_num`) and secondary / site in-charge contacts (`secondary_mobile_num`). Query builder logic must inspect table column schemas (`taluk`, `village`, `location` instead of assuming uniform column names) to avoid `Column not found` SQL exceptions.
